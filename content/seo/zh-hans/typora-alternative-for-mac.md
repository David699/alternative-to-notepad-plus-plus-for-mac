## 先确认：你想替代 Typora 的哪一部分？

**Mac 上选择 Typora 替代品，应先确定你最在意的是写作方式、价格、笔记组织，还是图片与文本处理。** 只因为另一款工具也能打开 `.md` 文件，并不意味着它会带来相同的写作体验。

如果你希望边写边看到排版、减少语法符号干扰，可以先继续试用 Typora；如果希望原文与结果始终并排，或经常在 Markdown 旁边处理 TXT、JSON、日志和列表，{{APP_NAME}} 是一个可以实际测试的方向。

本文由 {{APP_NAME}} 的开发者撰写。下面区分自家 App 的真实截图与第三方官方资料，不把功能列表当作速度或内存测试。想先体验自家 App，可以[打开 Mac App Store 下载页面](https://apps.apple.com/cn/app/id6759166160?ct=seo_typora_alternative_intro&mt=12)，核对当前价格、功能权限和系统要求。

## 喜欢直接排版时，先判断是否有必要换

Typora 的默认编辑方式让标题、列表、表格等内容在当前页面显示排版效果。它还提供专注模式和打字机模式，这些体验本身就是一些用户继续选择它的理由。

[![Typora 官方 Mac 示例，当前段落突出，其他内容淡化。](/images/seo/editors/typora-focus-official.webp)](/images/seo/editors/typora-focus-official.webp)

*配图来自 [Typora 官方专注与打字机模式文档](https://support.typora.io/Focus-and-Typewriter-Mode/)，属于官方文档中的历史界面示例。*

如果你每天主要写一篇长文，而且已习惯这种编辑方式，先用同一份文件比较段落输入、表格、图片和导出。仅仅增加几个自己很少用的按钮，不一定值得改变习惯。

如果主要顾虑是费用，先看[官方商店的许可说明](https://store.typora.io/)：本次核对时为一次性购买、15 天试用，个人许可最多可用于同一人的 3 台设备。不要误把它当成必须按月续费的工具。

## 按需求比较四个方向

| 你的主要需求 | 值得先看的工具 | 需要实际检查的地方 |
| --- | --- | --- |
| 连续写作，喜欢当前页面直接显示排版 | Typora | 输入手感、专注模式、主题与最终导出 |
| 已在代码项目里用 VS Code，也要改 README | VS Code 的 Markdown 预览 | 编辑与预览布局、需要的扩展、项目配置 |
| 整理互相关联的个人笔记 | Obsidian | 笔记链接、组织方式，以及是否需要同步或发布服务 |
| 核对源码与预览，编辑图片，并整理多种本地文本 | {{APP_NAME}} | 同步滚动、图片保存、文本处理和可配置 AI 是否符合任务 |

[VS Code 官方 Markdown 文档](https://code.visualstudio.com/docs/languages/markdown)说明了预览与双向同步滚动；已有 VS Code 的用户可以先试现有功能。因此，并排预览和滚动跟随并不是某一款编辑器独有的理由。

[Obsidian 官方介绍](https://obsidian.md/)侧重关联笔记与组织内容；其[价格页](https://obsidian.md/pricing)说明基础应用可免费使用，Sync 和 Publish 等附加服务另计。如果你的首要目标是笔记库，应该先测试这类组织方式，而不是只比较文字编辑工具。

这几种方向可以并存。例如在熟悉的写作工具里完成草稿，再用文本编辑器统一整理链接和列表。没必要为了一个偶尔使用的操作迁移全部资料。

## 什么时候值得试 {{APP_NAME}}？

### 你需要同时核对 Markdown 语法与预览

在左侧保留原文，右侧看结果，可以直接检查链接目的地、代码围栏和表格标记。滚动任一侧时另一侧跟随，小链条开启内容块的精确对齐；编辑文字后精确对齐自动关闭，预览仍会实时更新。

这种方式适合经常检查 README、教程或说明文档的人，也会占用更多横向空间。请用你平时的普通窗口大小试一下，再判断是否顺手。

### 文档里的图片需要修改文件尺寸

{{APP_NAME}} 的图片编辑面板提供裁剪、旋转和按比例调整尺寸。它能处理的是图片文件本身；这与只改变图片在页面中的显示比例不同。

编辑现有图片会写回引用的文件，先留好原图。自定义输出尺寸使用 Pro 的 Save Edited Image 操作。Typora 也有图片插入、路径管理和尺寸相关设置，具体可看其[官方图片文档](https://support.typora.io/Images/)，不要把“支持图片”当作两者的分界。

### 你想在 Markdown 中使用自己配置的 AI

API 是让 App 向你选择的 AI 服务发出请求的接口。在 AI Settings 中配置服务地址、模型和密钥，并满足 App 当前的 AI 功能使用权限后，可以用翻译、总结、纠正语法、改善表达、简化文字和解释代码等操作。AI 写作助手还提供 Markdown 排版等入口。

先选中一段需要处理的文字，例如一段发布说明。文字操作优先处理单一选区中的文字，没有选中文字时会使用当前文档；运行前确认范围，因为文字会发送到所配置的服务。返回结果后先审核，再应用或放弃，并重新查看预览。

普通 Markdown 编辑与预览不要求配置 AI。App 的购买或试用也不代表模型服务免费，具体用量、费用和数据处理规则应查看所选服务。选择替代品时，应把设置成本和输出审核一起考虑，而不是只看“带 AI”三个字。

### Markdown 只是你要处理的文本之一

如果你还会打开日志、TXT、JSON 和列表，可以试用多标签页、文件夹搜索、正则替换，以及可重复执行的文本处理步骤。正则是按文字模式查找内容的方法；Typora 本身也支持正则搜索和替换，不能因为要推荐替代品就忽略这一点。双方功能的逐项说明在[Typora 与 {{APP_NAME}} 对比](/zh-hans/typora-vs-notepad-plus-plus-plus-plus/)中。

## 换编辑器前，用副本完成这份检查

**复制文件与图片。** 普通 `.md` 文件可以先直接打开。相对路径是从文档所在文件夹出发寻找资源的写法；只复制 Markdown、不复制图片目录，可能导致图片缺失。保留原文件，不要第一步就覆盖整个资料库。

**核对结构。** 看标题、嵌套列表、任务、表格、脚注与链接。再检查数学公式、Mermaid 图和 HTML 等扩展内容，它们在不同阅读器中可能表现不同。

**检查主题依赖。** 如果原文依靠 Typora 主题、CSS 或 HTML 控制版式，不要假设换到另一款工具后会自动保持相同外观。先确认真正需要保留的是文字内容，还是完整的排版样式。

**测试最终交付。** 导出你真正要交付的格式并打开检查。Typora 的部分导出需要 Pandoc；{{APP_NAME}} 虽有多种导出菜单，也应核对实际结果。已有 DOCX 测试中，Mermaid 保留源码，Markdown 表格未变成 Word 原生表格，不能保证与预览完全一致。

**再试一段 AI 操作。** 如果 AI 是换工具的主要原因，只选择公开演示文字，检查发送范围、输出质量和费用，再考虑是否适合真实工作文件。
