## Keep the editor and preview in sync

**Scroll the editor and preview together:** open a saved `.md` file and enable **Preview** in the toolbar. The source stays on the left and the rendered document on the right. Scroll down in the editor and the preview follows; scroll the preview and the editor follows back. You can review either pane without repeatedly searching for the same passage in the other.

**Click the small chain button at the top of the divider to enable precise alignment.** The close-up below points to this control. In the enabled state shown, the chain button is blue and a blue line connects the selected source block to its rendered content.

[![Close-up of the real App with an orange arrow pointing to the blue chain button for synchronized editor and preview scrolling.](/images/seo/markdown-workbench/scroll-sync-chain-closeup.webp)](/images/seo/markdown-workbench/scroll-sync-chain-closeup.webp)

*Real App screenshot, cropped and enlarged, with an explanatory arrow added. Click the chain button shown by the arrow, then scroll either pane to review corresponding content together. The arrow and label are tutorial annotations, not App controls.*

Precise alignment adds space where needed so corresponding blocks—such as a short image reference and a tall rendered image—can line up. The blue highlight and connection line make the relationship visible. Clicking a rendered heading, table or image also takes you to its Markdown source.

[![Real App screenshot after scrolling the source, with math and a Mermaid sequence diagram aligned in the preview.](/images/seo/markdown-workbench/scroll-sync-real.webp)](/images/seo/markdown-workbench/scroll-sync-real.webp)

*Real App capture: the Math notes and Review conversation sections remain aligned after scrolling the editor. Scrolling the preview in the opposite direction was also checked.*

**Editing and preview updates:** when you change the Markdown text, the rendered preview updates. This is separate from scrolling the two panes together. Precise alignment turns off automatically after an edit to prevent alignment spacing from making the editor jump; click the chain button again when you want to review with exact block alignment. These features work with the local document, rather than cloud synchronization or collaborative editing.

## Crop, rotate and resize a Markdown image inside the App

Images are part of writing documentation. A screenshot may need a tighter crop, a rotated illustration may need correction, or an oversized asset may need smaller dimensions.

For a local image, click its preview to locate the source line, then use the **Edit Image** action beside that line. You can also open the Markdown context menu on the image reference. The image editor shows the original dimensions, a draggable crop box, rotation buttons and proportional width and height controls.

[![Real App image editor showing a mountain lake photograph and saved dimensions of 601 by 229 pixels.](/images/seo/markdown-workbench/image-crop-resize-real.webp)](/images/seo/markdown-workbench/image-crop-resize-real.webp)

*Real App capture: a 1200×457 landscape photograph is resized proportionally to 601×229, with the whole scene retained. The saved image file was checked and has those output dimensions.*

1. Drag over the image to select the area you want to keep.
2. Use **Rotate Left** or **Rotate Right** if its orientation needs changing.
3. Enter a width or height; the other dimension follows the aspect ratio.
4. Use **Save Edited Image** to apply the chosen dimensions. This sizing action is marked as a Pro feature. The separate **Save** action applies crop and rotation at the resulting crop size.

[![Real App image editor after rotating the mountain lake photograph clockwise.](/images/seo/markdown-workbench/image-rotate-real.webp)](/images/seo/markdown-workbench/image-rotate-real.webp)

*Real App capture: a clockwise rotation preview. This second operation was canceled; the photograph remains horizontal at the saved 601×229 dimensions.*

**Keep an original copy before editing an existing asset:** saving writes to that referenced image file. Our demonstration keeps an original image separately. The mountain lake photograph is by [Scott Goodwill on Unsplash](https://unsplash.com/photos/a-serene-mountain-lake-reflects-peaks-and-sky-Oifn0Pgl1Ug), used and resized under the [Unsplash License](https://unsplash.com/license). Relative image paths work when the Markdown file and asset folder stay together; macOS may ask you to authorize access to the containing folder.

## Edit Markdown tables with a grid

You can inspect a rendered table, locate its source and open **Adjust Table** from the inline action or Markdown context menu. The panel exposes the number of data rows and columns, editable cells, and left, center and right alignment controls. This is easier to review than counting every pipe character in a wide table.

[![Real App table editor showing three data rows, four columns, cell values and column alignment controls.](/images/seo/markdown-workbench/table-editor-real.webp)](/images/seo/markdown-workbench/table-editor-real.webp)

*Real App capture: the review-status table has three data rows and four columns. Progress is right aligned and Ready is centered. The panel was opened for inspection without changing the table.*

The file remains a normal Markdown table. For complex spreadsheets with formulas or merged cells, use a spreadsheet rather than expecting a Markdown table to replace one.
